# DeepWrite 长篇写作迁移设计

## 目标与边界

长篇写作以独立的 `deepwrite.long-book` 项目类型接入 DeepWrite。它参考
Write Claw 的长篇结构，但复用当前 DeepWrite 已验证的会话、审批、CAS、
事务、素材/技能绑定和主题组件。短篇 `book` 与剧本 `script` 的 schema、
目录、会话、设置和保存链路不扩展、不分支、不复用长篇持久化状态。

隔离原则：

| 层 | 长篇实现 | 与短篇/剧本的边界 |
| --- | --- | --- |
| 契约 | 独立 LongBook、LongWorkspace、LongLedger、LongAgentSettings | 不扩展 WorkspaceType/BookSchema/ScriptSchema |
| 存储 | 独立项目目录、manifest、索引、事务与 Catalog | 不读取或改写短篇/剧本项目文件 |
| 会话 | bookId + long agentId + root + chapterId | 不复用短篇/剧本草稿、审批或恢复 key |
| API | `deepwrite.long.*`、`longAgents`、`longAgentTeams` | 独立 IPC 命令和 Preload schema |
| Renderer | 独立三栏工作区和管理器 | 仅复用主题变量、PopupSelect、toast 等基础组件 |

## 长篇结构

工作区包含五个可见根节点和六个主智能体：

1. 世界观：可扩展分类，每类 Markdown 为内容权威。
2. 人物设计：人物元数据加核心档案、关系、当前状态、历史四文件。
3. 剧情设计：卷、剧情弧、章卡、故事事件、事件连接、叙事落点和伏笔线。
4. 专家正文：每章固定正文、人物状态、下一章交接三件套。
5. 连续性账本：连续提交前缀、六类摘要、证据、人物连续性变更与可逆记录。
6. 主智能体分别为世界观、人物、剧情、正文统筹、章节写手和连续性账本。

实体使用稳定 ID；文件路径由稳定 ID 推导，标题和排序变化不引起路径变化。
工作区索引只保存结构与文件引用，正文按需分页读取。新文件 revision 使用
UTF-8 字节长度和完整 SHA-256 的 `v2` 格式；旧 `v1` 8 位 revision 只用于
兼容读取，并在后续写入时升级。

## 修改与审批

Agent 只有查询能力和“形成提案”的能力，不直接写盘：

1. Runtime 从 Core 读取最新索引。
2. typed domain tool 接受业务字段，不接受路径、文件 ID、时间或 revision。
3. Runtime 生成稳定 ID、规范文件引用、CAS revision 和精确影响集。
4. Renderer 展示完整结构变化、文件全文、before/after 和级联影响。
5. 用户批准前先保存当前编辑器；Core 再执行 schema、权限和 CAS 校验。
6. Store 通过可恢复事务一次提交业务文件、索引和 manifest。
7. 成功后同步编辑器基线；冲突时保留脏稿并提示重新核验。

剧情智能体可以创建空白章节三件套，但不能通过通用结构工具写正文。正文只能
由章节写手的三文件原子提案写入。

Renderer 在保存审批前先锁定编辑器，并在保存后再次核对活动书籍和提案身份，
防止双击审批、保存期间继续编辑或上下文切换造成旧快照落盘。串行计划运行时，
只有与当前书籍、章节、阶段、Agent、session 和 run 全部匹配的章节/账本提案
可以批准或影响计划状态；此前残留的结构、错章或旧会话提案不能推进计划。

所有长篇写入都经过项目级跨进程独占锁；事务进入 prepared 状态后会在真正
替换文件前重新校验全部前置 revision。锁文件包含进程和随机身份，只有确认
持有者已退出且锁的 inode/身份未变化时才可回收，避免过期锁回收中的 ABA
误删。等待方读取锁时若持有方恰好完成释放，会把路径消失/换代视为重试信号，
不会把正常并发转换成 `ENOENT`。manifest、索引、Markdown 和账本记录分别
执行角色化字节上限，拒绝超限内容进入事务。

## 章节编排

长篇只允许 `chapter`、`arc`、`volume` 三种写作范围，不允许整本并发写作。
章节始终按卷序和卷内叙事顺序串行处理：

1. `empty`：三件套均为空，启动新的章节写手运行。
2. `partial`：存在缺失文件，启动新的章节写手运行并要求只补齐缺项。
3. `ready_to_commit`：三件套完整，跳过写作并启动新的连续性核验运行。
4. 章节写入批准且保存、刷新成功后，才进入连续性阶段。
5. 连续性提交批准且落盘成功后，才推进范围内下一章。
6. 任一步失败都停在当前章，可重试但不能跳章。

每章写手与连续性核验都使用 fresh session/run，避免上一章上下文污染。
取消计划时先隔离对应 session 并清除其待审提案，再失效编排 epoch；尚未取得
run ID 的请求会立即换 session，并在受理结果迟到后补发中止。已经取得 run ID
的运行先捕获中止请求再换 session，因此迟到事件不能重新入队或启动下一阶段。

## 连续性账本

新提交必须包含：

- 非空提交说明；
- 时间线、人物、势力、境界、伏笔和连续性六段非空摘要；
- 本章每个叙事落点和伏笔节拍的 committed/missed 判定及非空证据；
- 人物关系或当前状态的完整审计替换，或人物历史的审计追加。

人物历史只能由后端追加，并自动写入章节 ID、提交 ID 和提交时间。账本不能
改写核心人物档案、全书线、世界观或章节三件套。每条可逆记录保存精确
before/after；只允许回滚最后一条可逆提交。已提交章节和账本接管的人物文件
固定索引 revision，检测到外部篡改立即停止，而不是静默接纳。

已提交事实形成不可跨越的结构锚点：对应章节、卷序、剧情弧、事件、人物引用、
叙事落点、伏笔节拍和真相事件不能通过重排或级联删除改变。

提交和回滚会在同一事务中复核完整 pinned 集合：既有账本记录、已提交章节
三件套以及账本接管的人物连续性文件都必须与索引一致。Runtime 使用 Core
刚读取的实时 revision 构造提案，模型输入中的路径、文件 ID 和 revision
不会成为写入依据。

## Write Claw 迁移

迁移始终在同级 staging 目录完成校验，再原子重命名为正式项目；源文件只读，
符号链接和硬链接均拒绝。

- v1/v2：已提交章缺少现代审计字段时，生成稳定、只读、不可逆检查点，并使用
  明确的未知时间占位。
- v3–v5：标记已提交的章节必须有 commit ID、有效提交时间和对应时间线证据；
  缺任一项即拒绝迁移。
- 有完整提交链时恢复连续叙事前缀、落点/伏笔判定和账本记录。没有精确
  before/after 的旧记录绝不标记为可逆。
- 旧绑定、记忆、孤立账本条目、附件和无法结构化的原文以只读、可搜索迁移证据
  保留，不静默丢弃。
- 每个 drop、merge、coerce 和未解析引用都记录原始值、来源位置、决策与
  完整 ID 映射；原始源文件快照一并保留，迁移结果可追溯而不是只保留摘要。
- 参考项目每章产生一份 stage 和三份正文投影；经典 ZIP 可读取至 65,534 个
  条目，并同时受 256 MiB 压缩包、512 MiB 总解压量、64 MiB 路径总量和异常
  压缩率约束。权威 book/workspace JSON 单项上限为 128 MiB，普通附件仍为
  32 MiB。
- 超量世界观条目、换行标题、保留标记和超大正文会保守规范化，完整原值写入
  只读证据。大量小附件按 UTF-8 字节预算聚合成可搜索证据包，不会耗尽
  10,000 个世界观索引槽；常规迁移仍保留“书籍记忆”“账本”等原语义标题。

可移植包包含 manifest、索引、全部 Markdown 和账本记录的 SHA-256；导入时
交叉核对 record 与 index entry、提交顺序、章节、判定集合及 revision。
导出采用同目录临时文件、持久化恢复日志和目录 fsync；覆盖前再次校验目标摘要，
并发修改时保留外部内容、拒绝覆盖。恢复日志使用独占创建，不能清理其他进程
正在使用的日志。同一目标的并发导出使用精确命名的唯一租约竞争，活动租约持续
心跳续期；死亡进程、PID 复用和异常遗留的过期租约会按文件身份安全回收，相似
前缀的普通文件不会被当成租约。

## 设置与权限

长篇六角色和长篇智能体团队使用独立配置存储。系统提示词、快捷语、模型和读取
范围可配置；写入根和能力由内置角色固定，不能在设置中扩大。子智能体继承所属
长篇角色的受限工具，修改仍进入同一审批链。

Renderer 以每本书的单调刷新时钟原子发布索引和摘要；刷新失败时暂停发送并
提供重试，不用半新半旧状态启动智能体。串行计划运行期间统一阻止跨书切换、
导入迁移、结构和绑定修改、回滚、移除以及对话切换。长篇角色/团队的加载、
保存、错误和重试状态与短篇、剧本完全隔离。

## 验收

交付前至少验证：

- 长篇创建、关闭、重开、搜索、导入、导出和移除；
- 世界观、人物、剧情全部 typed CRUD、重排和级联预览；
- chapter/arc/volume 串行写作，三态 readiness、fresh session 和失败停止；
- 三件套原子保存、连续性提交、最后提交回滚和导入后回滚；
- 500+ 文件事务、200+ 章节 Catalog、Unicode 分页和搜索；
- 外部篡改、CAS 冲突、跨进程并发、锁 ABA、符号链接、硬链接、事务和导出
  中断恢复；
- 长篇设置持久化和崩溃草稿恢复；
- 全仓 typecheck、lint、test、build、Renderer smoke；
- 同一验收中重新运行短篇和剧本的创建、写作与保存回归。
